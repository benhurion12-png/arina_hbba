# HBBA — экспертная система первичного медицинского триажа

HBBA помогает пользователю отметить область дискомфорта на интерактивной карте тела, описать симптомы и получить первичную оценку срочности, рекомендуемого специалиста и дальнейших действий.

> Система не ставит диагноз и не заменяет очную консультацию врача. При опасных симптомах необходимо обращаться за экстренной медицинской помощью.

## Как устроен проект

Проект полностью запускается в Docker и состоит из трёх сервисов:

- `web` — интерфейс на Next.js: регистрация, карта тела, форма анализа, история и панель администратора;
- `api` — Express API, авторизация, экспертные правила, обработка PDF/TXT и работа с Prisma;
- `postgres` — PostgreSQL, где хранятся пользователи и результаты анализов.

Клиент регистрируется на странице `/register` и получает роль `CLIENT`. Администратор создаётся автоматически из настроек `.env` и может просматривать пользователей, статистику и блокировать учётные записи.

## Что потребуется

- Git;
- Docker Desktop для Windows/macOS или Docker Engine с Compose для Linux.

Node.js и PostgreSQL устанавливать на компьютер не требуется.

## 1. Клонирование проекта

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd Human_Body
```

Вместо `<URL_РЕПОЗИТОРИЯ>` укажите HTTPS- или SSH-адрес репозитория.

## 2. Создание `.env`

В репозитории находится файл `.env.example`. Создайте из него рабочий `.env`.

PowerShell в Windows:

```powershell
Copy-Item .env.example .env
notepad .env
```

Linux, macOS или Git Bash:

```bash
cp .env.example .env
```

Перед первым запуском проверьте и измените следующие значения:

```dotenv
POSTGRES_PASSWORD=сложный_пароль_базы
JWT_SECRET=длинная_случайная_строка_не_короче_32_символов
ADMIN_NAME=Имя администратора
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=сложный_пароль_администратора
```

Основные переменные:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_DB` | Имя базы PostgreSQL |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `JWT_SECRET` | Секрет для подписания пользовательских сессий, минимум 32 символа |
| `ADMIN_NAME` | Имя первоначального администратора |
| `ADMIN_EMAIL` | Email для входа администратора |
| `ADMIN_PASSWORD` | Пароль первоначального администратора |
| `WEB_PORT` | Порт сайта, по умолчанию `3000` |
| `API_PORT` | Локальный порт API, по умолчанию `4000` |
| `POSTGRES_PORT` | Локальный порт PostgreSQL, по умолчанию `5433` |
| `COOKIE_SECURE` | Для локального HTTP — `false`, для HTTPS — `true` |

`.env` содержит секреты и не должен попадать в Git. Он уже добавлен в `.gitignore`; в репозиторий следует коммитить только `.env.example` без настоящих производственных паролей.

## 3. Запуск проекта

Из корня проекта выполните:

```bash
docker compose up --build -d
```

При первом запуске Docker:

1. скачает необходимые базовые образы;
2. соберёт Next.js и Express;
3. запустит PostgreSQL;
4. применит миграции Prisma;
5. создаст администратора из `.env`;
6. запустит сайт и API.

Первичная сборка может занять несколько минут.

## 4. Проверка запуска

```bash
docker compose ps
```

У контейнеров `hbba-web`, `hbba-api` и `hbba-postgres` должен появиться статус `healthy`.

Откройте в браузере:

- приложение: `http://localhost:3000`;
- регистрация клиента: `http://localhost:3000/register`;
- вход: `http://localhost:3000/login`;
- проверка API: `http://localhost:3000/api/health`.

Для входа администратора используйте `ADMIN_EMAIL` и `ADMIN_PASSWORD`, заданные в `.env` до первого запуска.

> `ADMIN_PASSWORD` используется только при первоначальном создании администратора. Его изменение в `.env` не меняет пароль уже существующей учётной записи.

## Управление проектом

Посмотреть логи:

```bash
docker compose logs -f web api postgres
```

Пересобрать проект после изменения исходного кода:

```bash
docker compose up --build -d
```

Применить изменения только из `.env` без пересборки образов:

```bash
docker compose up -d --force-recreate
```

Остановить проект, сохранив базу данных:

```bash
docker compose down
```

Запустить остановленный проект снова:

```bash
docker compose up -d
```

Данные PostgreSQL сохраняются в Docker volume `hbba_postgres_data` и не удаляются обычной командой `docker compose down`.

Полностью удалить контейнеры вместе со всеми пользователями и анализами:

```bash
docker compose down -v
```

> Внимание: команда с `-v` безвозвратно удаляет базу данных проекта.

## Если проект не запускается

Посмотрите состояние и последние логи:

```bash
docker compose ps
docker compose logs --tail 100 web api postgres
```

Если порт `3000`, `4000` или `5433` занят, измените соответствующий `WEB_PORT`, `API_PORT` или `POSTGRES_PORT` в `.env`, затем пересоздайте контейнеры:

```bash
docker compose up -d --force-recreate
```

## Структура проекта

```text
apps/
  web/                 Next.js интерфейс и Dockerfile
  api/                 Express API, Prisma, экспертная система и Dockerfile
docker-compose.yml     Запуск web, api и PostgreSQL
.env.example           Пример переменных окружения
.dockerignore          Исключения Docker build context
```

Для публичного развёртывания используйте HTTPS, установите `COOKIE_SECURE=true` и разместите reverse proxy с TLS перед сервисом `web`.
